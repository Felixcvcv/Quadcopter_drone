# 四轴无人机仿真器

用键盘当遥控器，在带**高楼、大桥、树林**的 3D 场景里飞这套固件。

飞行控制部分是**把 `firmware/flight_controller` 里的算法原样移植成 JavaScript**——姿态解算、串级 PID、定高状态机、解锁状态机、2.4G 帧协议、任务调度周期，都是同一份逻辑。所以在仿真里看到的振荡、回正快慢、定高下沉，都是固件那组参数的真实表现，不是另写一套"仿真用"的控制律。

---

## 快速开始

**方式一：直接用浏览器打开**

```bash
# 在仓库根目录
python -m http.server 8000
# 然后浏览器访问 http://127.0.0.1:8000/simulator/
```

之所以需要一个静态服务器：页面按普通 `<script>` 加载模块，虽然 `file://` 也能加载脚本，但某些浏览器对本地文件的安全策略会拦截 three.js 的纹理与跨域请求，用本地服务器最省事。

**方式二：GitHub Pages**

仓库设置里开启 Pages（Source 选 `main` 分支根目录），然后访问
`https://<你的用户名>.github.io/Quadcopter_drone/simulator/`。

> 首次打开需要联网：three.js 通过 CDN 引入。要离线使用，把 `three.min.js` 下载到 `js/vendor/` 下并改掉 `index.html` 里的 script 地址即可。

## 键盘操作

遥控器是 **Mode 2** 布局：左摇杆管油门与偏航，右摇杆管俯仰与横滚。

| 按键 | 作用 |
| --- | --- |
| <kbd>W</kbd> <kbd>S</kbd> | 油门增 / 减（松手保持，和真摇杆一样） |
| <kbd>A</kbd> <kbd>D</kbd> | 偏航左 / 右（松手回中） |
| <kbd>↑</kbd> <kbd>↓</kbd> | 俯仰前 / 后（松手回中） |
| <kbd>←</kbd> <kbd>→</kbd> | 横滚左 / 右（松手回中） |
| <kbd>Shift</kbd> | 按住 = 微调速度，方便精修姿态 |
| <kbd>空格</kbd> | 自动执行解锁序列（油门最高 1.2s → 最低 1.2s） |
| <kbd>E</kbd> | 遥控器右上键：短按切定高；**长按 >0.5s 重校准摇杆零偏** |
| <kbd>Q</kbd> | 遥控器左上键：关机 |
| <kbd>Z</kbd> <kbd>X</kbd> | 横滚零偏微调 −/+ |
| <kbd>C</kbd> <kbd>V</kbd> | 俯仰零偏微调 +/− |
| <kbd>1</kbd> <kbd>2</kbd> <kbd>3</kbd> | 三种**第三人称**视角：追尾跟随 / 环绕 / 俯视跟随 |
| 鼠标拖拽 / 滚轮 | 环绕视角下旋转、缩放 |
| <kbd>T</kbd> | 时间倍速 1x → 0.5x → 0.25x（慢动作看控制环路） |
| <kbd>J</kbd> | 注入 2.4G 干扰（模拟断链，看失联保护） |
| <kbd>H</kbd> | 隐藏 / 显示所有面板 |
| <kbd>R</kbd> | 复位（重新校准零偏并把飞机放回起降场） |

**用鼠标拖摇杆**：底栏左边就是虚拟遥控器，两个圆形摇杆。

- **左杆** = 油门（上下）+ 偏航（左右）。油门没有弹簧，**松手保持**在当前位置；偏航松手回中。
- **右杆** = 俯仰（上下）+ 横滚（左右）。松手**自动回中**，和真摇杆的弹簧一样。
- 在摇杆圆圈内任意位置按住拖动即可，拖动时旋钮会跟手；双击某根摇杆让它立刻回中。
- 键盘和鼠标是**同一个通道值的两个入口**，互相同步：用键盘打杆时摇杆旋钮也会跟着动。

三种视角都是第三人称（相机始终在机身外部）：

| 视角 | 说明 |
| --- | --- |
| 追尾跟随 | 相机在机尾后上方，视线朝机头前方，最接近平时看别人飞无人机的手感 |
| 环绕 | 相机绕飞机转，拖动鼠标旋转、滚轮缩放，适合查看姿态与外观 |
| 俯视跟随 | 相机在飞机上方偏后往下看，适合在楼群里盯住飞机位置 |

### 第一次飞建议这样操作

1. 等日志出现 `上电完成`（此时已完成陀螺仪零偏校准，**飞机必须静止在地面**）。
2. 按 <kbd>空格</kbd>，看状态条里"已解锁"亮起。
3. 按住 <kbd>W</kbd> 把油门推到 650 左右（日志里会打印本机的悬停油门，约 629），飞机会离地。
4. 用 <kbd>↑</kbd> 前飞，用 <kbd>←</kbd> <kbd>→</kbd> 横滚，飞到城区或大桥上去看看。
5. 按 <kbd>E</kbd> 开定高，此时松开车门飞机也会保持高度。
6. 按 <kbd>J</kbd> 注入干扰，观察 1.2 秒后自动上锁并退出定高——这就是固件的失联保护。

## 界面说明

| 区域 | 内容 |
| --- | --- |
| 顶部 | 链路 / 解锁 / 定高 / 电源状态，4 个 LED（直接反映固件灯控任务算出的引脚电平） |
| 左栏 | 姿态地平仪、欧拉角、激光测距与定高目标、Z 轴速度估计、遥控器 4 通道值 |
| 右栏 | 4 路电机 PWM、4 个 PID 输出、姿态与高度波形（近 6 秒） |
| 底部 | 虚拟遥控器（鼠标可拖）、按键说明、运行日志 |

**电机转速条**是最值得盯的地方：它直接对应固件写进定时器比较寄存器的值。悬停时四条基本等高，打杆时能看到对角/同侧的两两消长。

## 场景

| 元素 | 说明 |
| --- | --- |
| 起降场 | 原点处的 H 标识停机坪，所有复位都回到这里 |
| 城区 | 东北方向 37 栋楼 + 3 座地标塔楼（最高 132 m），带路网，越靠市中心越高 |
| 跨河大桥 | 南侧，跨河道；桥面、桥塔、主缆与吊索都有，**可以降落在桥面上**，桥塔会撞 |
| 树林 | 西南方向约 490 棵树，地形向西南缓坡抬升 |
| 河道 | 东西向水面，桥从这里跨过去 |
| 地形 | 解析函数生成，渲染网格与碰撞/测距用的是**同一个高度函数**，看到的和飞到的完全一致 |

撞上楼体或桥塔会判定坠机（电机停转，按 <kbd>R</kbd> 复位）；着陆垂直速度超过 3.2 m/s 也算坠机。

## 命令行自检

浏览器里的代码和自检用的是**同一份源文件**（Node 里用 `vm` 把那些普通脚本跑进同一个全局环境），不存在"测试版"和"发布版"漂移。

```bash
node simulator/tools/selftest.mjs
```

覆盖内容：

- 快速平方根倒数的精度（与固件注释里的 5e-6 对照），以及"两次牛顿迭代 vs 一次"
- 2.4G 帧的三级校验：帧长、帧头、载荷长度、8 个单比特翻转全部被拦
- AHRS 姿态估计在带陀螺仪零偏的情况下收敛到真值（误差 < 0.5°）
- 三个姿态环都是负反馈：受扰后收敛，残余角速度 < 0.03 rad/s
- 解锁状态机：油门高低各保持不足 1.2s 不解锁；停最低 60s 自动上锁
- 断链保护：0.2s 内仍算连接，超过 1.2s 判失联并上锁退定高
- 定高环：漂移 < 0.01 m，受扰后能拉回
- 未解锁时 4 个电机必须全为 0 且飞机不离地

要重新整定物理参数：

```bash
node simulator/tools/tune.mjs
```

它会两阶段搜索（粗搜 + 局部细化）物理参数空间，判据是"三个姿态轴受扰后收敛得又快又稳，同时悬停油门落在手杆中段"。

## 已知简化

这些地方与真机不同，看数据时留意：

| 简化 | 影响 |
| --- | --- |
| 用双精度浮点，固件是单精度 | 仿真里的数值漂移比真机小 |
| 没有桨叶挥舞/动态入流模型，转动阻尼用了等效系数 | 大机动时的气动细节不准 |
| 加速度计只算重心处的比力 | 没计入转动加速度在传感器安装位置上的分量 |
| 树没有碰撞，激光也不打树叶 | 树冠可以穿过去 |
| VL53L1X 只按量程截断 + 加噪声 | 没有真实芯片的距离状态码（量程外/信号弱等） |
| 射频链路是概率模型（距离衰减 + 遮挡 + 比特错误） | 不是真实的 2.4G 信道仿真 |
| 沿用的固定 0.5ms 时间片 | 真机是抢占式调度，有任务切换开销 |
| 机身按 3 倍绘制 | 视觉尺寸接近 300mm 级机型，与 100mm 轴距的物理模型不一致（只影响观感） |

另外，仿真里能观察到两个**固件本身的特点**（不是仿真的 bug）：

1. **切入定高时会有一次下沉**。Z 轴速度估计里的位置项在第一次计算时用到 `heightPID.measure`，而它的初值是 0，于是头一拍算出一个很大的速度估计值，被限幅后表现为一次明显的掉高，需要几秒才恢复。真机上有同样的现象。
2. **悬停时高度靠油门配平**。定高环是纯 P（Ki = 0），稳态误差靠积分项消不掉；要更稳的定高需要给高度环加 I，并同时配好积分限幅。

深入的技术说明见 [docs/05-仿真器.md](../docs/05-仿真器.md)。
