# 系统架构

## 1. 整体组成

系统由两块独立的板子构成，各自运行一套完整的 FreeRTOS 应用，通过 2.4G 单向数据链路连接：

```
      遥控器 (remote_controller)                飞控板 (flight_controller)
 ┌───────────────────────────────┐        ┌───────────────────────────────┐
 │ 摇杆 ADC × 4 ──┐               │        │               ┌── 4× 空心杯电机 │
 │ 按键 × 6 ──────┤               │        │               │   (PWM 18kHz)   │
 │ OLED 128×64 ───┤   STM32F103   │  2.4G  │   STM32F103   ├── 4× LED        │
 │                ├──  C8T6       │◀───────┼──  C8T6       │                 │
 │ IP5305T ───────┘   FreeRTOS    │  Si24R1│   FreeRTOS    ├── MPU6050 (I2C1) │
 │                    USART1(调试)│        │               ├── VL53L1X (I2C2) │
 └───────────────────────────────┘        │               └── IP5305T       │
                                           │                   USART2(调试)  │
                                           └───────────────────────────────┘
```

链路是单向的：遥控器只发，飞控板只收。飞控板不向遥控器回传任何飞行数据，因此遥控器上显示的是**本地摇杆行程量**，而不是飞行姿态。

## 2. 分层结构

代码分为四层，依赖关系单向向下：

| 层 | 目录 | 职责 | 可以依赖 |
| --- | --- | --- | --- |
| 应用层 | `App/` | 任务编排、业务流程、控制律 | 公共层、硬件接口层 |
| 公共层 | `Common/` | 类型定义、姿态解算、PID、滤波、日志 | 硬件接口层（仅调试） |
| 硬件接口层 | `Inf/` | 把外设封装成"电机 / 传感器 / 无线模块"这样的器件语义 | HAL、CubeMX 生成的句柄 |
| 驱动层 | `Core/` `Drivers/` `Mid/` | CubeMX 生成的外设初始化、ST HAL、FreeRTOS | — |

约束：

- 应用层不出现 `HAL_xxx` 调用（读写具体寄存器），只调用 `Inf_xxx` 语义接口。
- 公共层的算法不依赖任何外设，只处理数据，便于单独验证。
- `Com_Config.h` 是全局类型的唯一来源（状态枚举、数据结构、协议常量），避免各模块各定义一套。

## 3. 数据流

### 飞控板（`flight_task`，4 ms 周期）

```
MPU6050 ──I2C读6轴──▶ 零偏补偿 ──▶ 角速度: 一阶低通
                                  加速度: 卡尔曼(逐轴)
                                        │
                                        ▼
                            四元数姿态解算 + 加速度PI补偿
                                        │
                                        ▼
                                 欧拉角 pitch/roll/yaw
                                        │
                     ┌──────────────────┴──────────────────┐
                     ▼                                     ▼
            姿态串级 PID ×3                          高度串级 PID ×2
        (角度外环 → 角速度内环)                  (VL53L1X 高度 → Z轴速度)
                     │                                     │
                     └──────────────────┬──────────────────┘
                                        ▼
                            X字型机架电机分配 + 限幅
                                        │
                                        ▼
                              4 路 PWM 写入定时器
```

### 遥控器

```
ADC(DMA) ──▶ 极性/量程换算 ──▶ 扣零偏 ──▶ joyStick 结构体 ──▶ 组帧 ──▶ Si24R1 发送
                                              │
                                              └──▶ OLED 显示
GPIO 按键 ──▶ 消抖/长按判定 ──▶ 修改零偏 / 置位关机与定高命令
```

## 4. 任务与同步

### 为什么用 FreeRTOS

飞控里存在多个**周期不同、实时性要求不同**的工作：控制律要 4 ms 严格周期执行，通讯要 6 ms 轮询，LED 指示和人机交互只需要几十毫秒。用裸机前后台会在"主循环里塞一堆延时"的方向上越走越远，任务划分能把这些周期解耦。

### 同步手段

| 场景 | 手段 | 说明 |
| --- | --- | --- |
| 周期任务节拍 | `vTaskDelayUntil()` | 相对上一周期的绝对延时，避免执行时间累积成周期漂移 |
| 关机命令（通讯任务 → 电源任务） | 任务通知 `xTaskNotifyGive()` / `ulTaskNotifyTake()` | 比队列更轻，且支持带超时等待 |
| 共享数据快照 | `taskENTER_CRITICAL()` | 只保护几条赋值，不跨越任何阻塞调用 |

### 临界区纪律

**临界区里绝对不能调用会阻塞的 API。** `taskENTER_CRITICAL()` 在 Cortex-M3 上会执行 `CPSID I` 关中断，此时 SysTick 不再产生中断，`vTaskDelay()` 等待的时基永远不会推进——任务将永久卡死，且看门狗（本工程未启用）也无法复位。

判断原则：临界区只用来把"读多个相关变量"变成一个原子快照，长度控制在微秒级。任何 I2C/SPI 事务、任何延时都必须放在临界区之外。

### 总线归属

| 总线 | 飞控板使用者 | 遥控器使用者 |
| --- | --- | --- |
| I2C1 | MPU6050（仅 `flight_task`） | — |
| I2C2 | VL53L1X（仅 `flight_task`） | — |
| SPI1 | Si24R1（仅 `comm_task`） | Si24R1（仅 `comm_task`） |
| 软件 SPI | — | OLED（仅 `display_task`） |
| ADC1+DMA | — | 摇杆（`joystick_task` 读缓冲，DMA 后台写） |

每条总线只有一个任务访问，因此不需要额外的互斥量；ADC 的 DMA 缓冲区由硬件写、任务读，用一次短临界区取快照即可。

## 5. 电源管理

两块板子都用 IP5305T 作为电源管理芯片。它对外的接口只有一个按键信号：**短按脉冲切换开关机**。

- 开机：拉低 100 ms 再拉高
- 关机：连续两次短按（中间间隔 500 ms）
- 防自动关机：IP5305T 在无负载一段时间后会自动关机，因此 `power_task` 在 10 s 内没等到关机命令时，就补发一次短按脉冲维持供电

## 6. 启动顺序

```
main()
 ├─ HAL_Init()                          系统时钟与 SysTick
 ├─ SystemClock_Config()                72 MHz
 ├─ MX_xxx_Init()                       外设初始化
 └─ App_Task_FreeRTOSStart()
      ├─ debug_start()
      ├─ App_Flight_Start()             电机 PWM / MPU6050(含静止校准) / VL53L1X
      ├─ App_Communication_Start()      Si24R1 自检并配置为收发模式
      ├─ xTaskCreate(start_task)
      └─ vTaskStartScheduler()          从这里开始不再返回
             └─ start_task: 创建业务任务后 vTaskDelete(NULL)
```

**注意**：MPU6050 的零偏校准（`Inf_MPU6050_Calibrate()`）在调度器启动之前执行，内部用 `HAL_Delay()` 阻塞等待机身静止，所以上电瞬间必须让飞机保持水平静止。
