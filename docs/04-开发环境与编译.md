# 开发环境与编译

## 1. 工具链

| 工具 | 版本 / 说明 |
| --- | --- |
| Keil MDK-ARM | 5.x |
| ARM Compiler | **AC5**（ARMCC 5.06 或更高） |
| STM32F1xx Device Family Pack | 3.x（安装到 Keil 的 Pack 里） |
| STM32CubeMX | 用于重新生成外设初始化（可选，工程已含生成结果） |
| 调试器 | ST-Link V2 或 J-Link |

工程用的是 **ARM Compiler 5**。切到 ARM Compiler 6（armclang）需要一并处理 MicroLIB 与启动文件的差异，工程未做适配。

## 2. 工程与目录对应关系

两个工程各自独立，互不依赖：

| 工程文件 | Keil Target 名 | 源码根目录 |
| --- | --- | --- |
| `firmware/flight_controller/MDK-ARM/FlightController.uvprojx` | `FlightController` | `firmware/flight_controller/` |
| `firmware/remote_controller/MDK-ARM/RemoteController.uvprojx` | `RemoteController` | `firmware/remote_controller/` |

Keil 工程里的源文件路径都是相对 `MDK-ARM/` 目录的（例如 `..\App\flight\App_Flight.c`），因此整个目录可以任意移动位置，不需要重新配置路径。

编译产物输出到 `MDK-ARM/<Target 名>/` 下（`.axf` / `.hex` / `.map` 等），这些目录已在 `.gitignore` 中排除。

## 3. 编译

### Keil 图形界面

1. 打开 `.uvprojx`
2. 确认 `Options for Target → Target → Use MicroLIB` 已勾选
3. `F7` 编译，`F8` 下载

### 命令行批量编译

```bash
UV4.exe -b firmware/flight_controller/MDK-ARM/FlightController.uvprojx -j0 -o build.log
UV4.exe -b firmware/remote_controller/MDK-ARM/RemoteController.uvprojx -j0 -o build.log
```

`-b` 批量编译，`-j0` 不弹对话框，`-o` 指定日志文件。退出码：0 表示成功，1 表示有警告，2 表示有错误（`build.log` 里有详细内容）。

### 资源占用

| 工程 | Code | RO-data | RW-data | ZI-data |
| --- | --- | --- | --- | --- |
| FlightController | ≈ 34.9 KB | 432 B | 760 B | 16.0 KB |
| RemoteController | ≈ 16.5 KB | 3.8 KB | 156 B | 16.4 KB |

STM32F103C8T6 有 64 KB Flash 与 20 KB RAM。飞控的 ZI-data 里大头是 FreeRTOS 的 12 KB 堆，任务栈从中分配。

## 4. 编码相关的坑（重要）

这部分是实际踩过的，改动源码时请遵守。

### 4.1 源文件不要加 UTF-8 BOM

ARM Compiler 5 **不识别 BOM**，会把 BOM 的三个字节当成标识符的一部分，报出：

```
error: #7: unrecognized token
  锘?#ifndef __COM_IMU_H
```

工程内的源文件统一为 **UTF-8 无 BOM**。

### 4.2 字符串字面量里不要出现中文

ARMCC 5 按**系统 ANSI 代码页**（中文 Windows 上是 GBK）解析源文件。UTF-8 编码的中文会被错误地按 GBK 解码，例如"动"的 UTF-8 字节是 `E5 8A A8`，按 GBK 解读时 `A8` 会和后面的 `"`(0x22) 配对，把字符串的收尾引号"吃掉"，于是报出与真实原因完全不相干的错误：

```
error: #274: improperly terminated macro invocation
      debug_printfln("通讯模块的启�? 开�?");
```

**结论**：中文只允许出现在**注释**里；所有字符串字面量（日志、显示文本）保持 ASCII。工程里 `debug_printfln()` 的内容已全部改为英文。

### 4.3 Keil 编辑器显示中文注释乱码

源文件是 UTF-8，而 Keil 编辑器默认按 ANSI 打开。设置一次即可：

```
Edit → Configuration → Editor → Encoding  →  选 UTF-8
```

### 4.4 中文注释里还残留 GBK 的旧文件

如果从旧版本合并代码，用下面的脚本检查编码是否统一（GBK 的中文注释在 armcc 下能编译，但推送到 GitHub 会显示成乱码）：

```python
import pathlib

for p in pathlib.Path("firmware").rglob("*"):
    if p.suffix.lower() not in {".c", ".h"} or not p.is_file():
        continue
    raw = p.read_bytes()
    try:
        raw.decode("utf-8")
    except UnicodeDecodeError:
        print("非 UTF-8:", p)
```

## 5. 用 CubeMX 重新生成外设配置

两个板子的 `.ioc` 工程都在各自目录下：

- `firmware/flight_controller/FlightController.ioc`
- `firmware/remote_controller/RemoteController.ioc`

用 CubeMX 打开后可以查看/修改引脚分配与时钟树，重新生成时注意：

- 生成前确认 `Project → Toolchain/IDE` 选的是 **MDK-ARM V5**
- 生成只覆盖 `Core/` 与 `Drivers/` 下带 CubeMX 标记的区域，`App/`、`Common/`、`Inf/` 不会被触碰
- 用户代码务必写在 `/* USER CODE BEGIN xxx */` 与 `/* USER CODE END xxx */` 之间，否则重新生成会被清掉
- CubeMX 生成的 `main.c` 里，用户代码只在 `USER CODE` 段内

## 6. 调试手段

### 串口日志

- 飞控板：USART2，115200-8-N-1
- 遥控器：USART1

日志通过 `debug_printfln()` 输出，由 `Common/debug/Com_Debug.h` 里的 `DEBUG` 宏统一开关：

```c
#define DEBUG (1)   /* 1: 打开日志   0: 全部编译为空, 不影响实时性 */
```

飞控板的 `DEBUG` 默认为 1；遥控器默认为 0（避免日志拖慢显示刷新，需要时打开即可）。

日志格式为 `[文件名:行号] -- 内容`，方便直接定位。

> `printf` 重定向到串口依赖 Keil 的 **Use MicroLIB** 选项，未勾选时链接会失败。

### 波形上报

`Common/digital_scope/outputdata.c` 提供了一个 10 字节定长帧的输出接口，可对接 VOFA+ / J-Scope 一类上位机：

| 字节 | 内容 |
| --- | --- |
| 0 ~ 7 | 4 个通道，每个 2 字节，小端 |
| 8 ~ 9 | CRC16（多项式 0xA001，初值 0xFFFF），低字节在前 |

用法：把要观察的量写进 `OutData[0..3]`，再调用 `OutPut_Data()`。适合观察滤波前后波形、PID 输出的抖动情况。

### 关于 `Inf_Si24R1_RxPacket` / `TxPacket` 的临界区

这两个函数在调用点被 `taskENTER_CRITICAL()` 包住。飞控板上 `RxPacket` 只做几次 SPI 读（SPI1 时钟下耗时可忽略），遥控器上 `TxPacket` 内部带了轮询超时上限，因此即使射频异常也不会长时间关中断。

新加外设访问时，请遵守同一原则：**临界区内只做微秒级的原子操作**。

## 7. 常见编译问题

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `error: #7: unrecognized token` 且显示 `锘?` | 源文件带了 UTF-8 BOM | 去掉 BOM |
| `error: #274: improperly terminated macro invocation` | 字符串字面量里有中文 | 改成 ASCII |
| `identifier "xxx" is undefined` | 新增的 `.c` 未加入工程 | 在 Keil 里把文件添加到对应 Group |
| `L6218E: Undefined symbol` | 声明了但没定义，或漏加源文件 | 检查头文件声明与实现是否成对 |
| `printf` 无输出 | 未勾选 Use MicroLIB，或没包含 `Com_Debug.h` | 勾选 MicroLIB |
