# 姿态解算与串级 PID

本文对应代码：`Common/imu/Com_IMU.c`、`Common/pid/Com_PID.c`、`Common/util/Com_Filter.c`、`App/flight/App_Flight.c`。

## 1. 坐标系与姿态表示

机体系固连在飞机上，地理系水平静止：

- `pitch` 俯仰 —— 绕机体系 Y 轴，机头上下
- `roll` 横滚 —— 绕机体系 X 轴，机身左右倾斜
- `yaw` 偏航 —— 绕机体系 Z 轴，机头水平转向

姿态用**四元数** `q = (q0, q1, q2, q3)` 描述。相比欧拉角，四元数没有万向节死锁问题，且递推时只需一次归一化，数值上更稳定。

## 2. 姿态解算

### 2.1 为什么不能只用陀螺仪

陀螺仪积分能得到角度，但存在两个问题：

- **常值零偏**：静止时输出不是严格的 0，积分后角度会随时间线性漂移
- **随机漂移**：积分误差随时间累积

加速度计能测到重力方向，长期来看是绝对参考，不会漂移；但它对振动和线加速度极其敏感，短期噪声很大。

**结论：短期信陀螺仪，长期信加速度计。** 姿态解算要做的就是按这个思路把两者融合。

### 2.2 算法流程（每 4 ms 一次）

1. **由当前四元数提取重力方向**

   ```
   gx = 2(q1·q3 − q0·q2)
   gy = 2(q0·q1 + q2·q3)
   gz = 1 − 2(q1² + q2²)
   ```

   这三个量就是等效旋转矩阵的第三行，也就是"当前姿态下地理系的 Z 轴在机体系中的表示"。

2. **加速度归一化**

   `a = accel / |accel|`，用快速平方根倒数（见 2.4）代替 `sqrtf`。

3. **做叉乘得到姿态误差**

   ```
   e = a × g
   ```

   如果姿态估计准确，测量到的重力方向与估计的完全一致，叉乘为零；有偏差时叉乘的方向就是"应该往哪个方向修正"，大小反映偏差程度。

4. **PI 补偿到角速度**

   ```
   ω_corrected = gyro × (π/180 换算系数) + Kp·e + Ki·∫e dt
   ```

   `Kp = 0.8` 负责快速拉回，`Ki = 0.0003` 的积分项负责消掉陀螺仪的**常值零偏**——这是单靠 P 做不到的。

5. **一阶龙格库塔法更新四元数**

   ```
   q0 += 0.5·(−q1·ωx − q2·ωy − q3·ωz)·dt
   q1 += 0.5·( q0·ωx − q3·ωy + q2·ωz)·dt
   q2 += 0.5·( q3·ωx + q0·ωy − q1·ωz)·dt
   q3 += 0.5·(−q2·ωx + q1·ωy + q0·ωz)·dt
   ```

6. **归一化四元数**（用同一套快速平方根倒数）

7. **反解欧拉角**

   ```
   pitch = asin(2q0·q2 − 2q1·q3) × 180/π
   roll  = atan2(2q2·q3 + 2q0·q1, 1 − 2q1² − 2q2²) × 180/π
   yaw   = ∫ (gyroZ × 4000/65536) dt        （|角速度| > 0.5 °/s 时才积分）
   ```

   偏航角不做加速度补偿——加速度计测不到绕重力轴的旋转，所以偏航只靠陀螺仪积分，这也是它长期漂移的根本原因。

### 2.3 一个容易被忽略的坑：asin 的入参必须限幅

`asin(x)` 在 `|x| > 1` 时返回 **NaN**。四元数归一化后理论上 `|x| ≤ 1`，但浮点舍入会让它偶尔略微越界（例如 1.0000001），此时俯仰角变成 NaN，接着污染 PID 输出和电机分配，表现为飞机瞬间失控。

代码里对入参做了 `LIMIT(x, -1.0f, 1.0f)` 限幅。这类"数值边界"问题在仿真里几乎不会出现，但在真实飞行中迟早会遇到。

### 2.4 快速平方根倒数

Cortex-M3 没有硬件浮点单元，`sqrtf()` 是软件实现，在每次解算要调用两次（加速度归一化 + 四元数归一化）的情况下开销可观。这里用了经典的"魔数猜初值 + 牛顿迭代"：

```c
u.f = number;
u.i = 0x5f3759dfU - (u.i >> 1);          /* 用整数运算猜初值 */
u.f = u.f * (1.5f - (x2 * u.f * u.f));   /* 牛顿迭代 1 */
u.f = u.f * (1.5f - (x2 * u.f * u.f));   /* 牛顿迭代 2 */
```

两个细节：

- **用 `union` 做位模式转换**，不要用 `long*` 强转。指针强转会违反严格别名规则，是未定义行为；也不要用 `long`——它在不同平台上宽度不同。
- **两次牛顿迭代**：一次迭代的相对误差约 1.7×10⁻³，两次约 5×10⁻⁶。多一次迭代只增加几次乘加，但归一化精度提升了三个数量级，对姿态解算是划算的。

## 3. 滤波

原始数据进入解算之前先分级处理，两类信号的噪声特性完全不同：

| 信号 | 滤波器 | 参数 | 原因 |
| --- | --- | --- | --- |
| 角速度 | 一阶低通 | α = 0.8 | 波动小、用来积分，重点保相位，不宜过度平滑 |
| 加速度 | 一维卡尔曼（逐轴） | Q = 0.001，R = 0.543 | 受电机振动影响大，需要更强的抑制 |

一阶低通：

```
y[k] = α·y[k−1] + (1 − α)·x[k]
```

一维卡尔曼：

```
预测： P = P_last + Q
增益： K = P / (P + R)
更新： x̂ = x̂ + K·(z − x̂)
      P_last = (1 − K)·P
```

`R` 越大表示越不信任测量，滤波越平滑但跟随越慢。

这两处运算都刻意使用 **float**：Cortex-M3 上 `double` 要靠软件库再模拟一层，运算量数倍于 `float`，而这里的精度需求单精度完全够。

## 4. 串级 PID

### 4.1 为什么用串级

单环 PID 以角度为反馈，但角度的计算本身就依赖加速度计，而加速度计容易被振动污染——噪声直接进入 PID 的微分项，输出会非常"毛躁"。

串级结构把控制分成两层：

```
期望角度 ──▶ [外环 PID] ──▶ 期望角速度 ──▶ [内环 PID] ──▶ 电机
   ▲              ▲                              ▲
   │              │                              │
  实测角度 ───────┘                    实测角速度 ─┘
```

- **外环（角度环）**：噪声大但反映最终目标，只用一个较小的 P
- **内环（角速度环）**：陀螺仪输出干净、响应快，由它承担抗扰动的任务

内环把外环的噪声"挡"在外面：外环输出的是期望角速度，即使外环有少量噪声，内环也能快速跟踪；而外部扰动会被内环先一步抑制，不会等到角度变化才响应。

### 4.2 实现

`PID_Struct` 把误差定义为 **测量值 − 期望值**（与常见写法相反），因此本工程的比例系数为负表示正反馈方向正确。这一点在调参时要注意：**先确认极性，再调大小**。

```c
float error = pid->measure - pid->desire;
float pV = pid->kp * error;
pid->integral += pid->ki * error * pid->dt;
float dV = pid->kd * (error - pid->lastError) / pid->dt;
pid->result = pV + pid->integral + dV;
```

`Com_PID_CascadePID(out, in)` 把外环输出直接赋给内环期望值，再算一次内环。

### 4.3 三个工程化的处理

**（1）积分限幅**

积分项会累积：只要误差存在，积分值就持续增大，即使输出早已饱和。当误差反向时，需要先把这一大堆积分"消耗"完才能退出饱和，表现为明显的过冲和迟滞。`PID_Struct` 提供了 `integralMin` / `integralMax`，上下限相等时表示不启用。

**（2）输出限幅**

`outMin` / `outMax` 同理。定高的 Z 轴速度环就配了 ±150 的限幅，原来这个限幅是在赋值处临时做的，现在收到 PID 结构体里，语义更清楚。

**（3）偏航角的最短路径**

偏航角是周期量。期望 0°、实测 359° 时，直接相减得到 −359° 的大误差，控制器会让飞机反向猛转一整圈。`PID_Struct` 的 `isAngle` 置 1 后，误差会被折算到 (−180°, 180°]，始终走最短路径：

```c
static float Com_PID_WrapAngle180(float deg)
{
    while(deg > 180.0f)   deg -= 360.0f;
    while(deg <= -180.0f) deg += 360.0f;
    return deg;
}
```

**（4）重新进入闭环前清状态**

`Com_PID_Reset()` 清零积分、上次误差和输出。重新解锁、重新进入定高时调用，避免上一次飞行残留的积分量造成输出突跳。

## 5. 定高

### 5.1 结构

高度环同样是串级，但周期降到 20 ms（每 5 个控制周期算一次），因为激光测距的更新率和噪声水平都远不如 IMU：

```
期望高度 ──▶ [高度环 Kp=-1.4] ──▶ 期望Z速度 ──▶ [Z速度环 Kp=-1.3, Kd=-0.08] ──▶ 叠加到4个电机
   ▲                                              ▲
   │ VL53L1X 测距                                  │ 互补滤波估计
   └──────────────────────────────────────────────┘
```

### 5.2 Z 轴速度的互补滤波

速度无法直接测量，只能估计。两种途径各有缺陷：

- **加速度积分**：响应快，但有累积漂移
- **高度差分**：长期不漂，但噪声大、滞后明显

互补滤波按权重融合：

```
v = 0.9 · (v_prev + (a_z − a_static)·dt) + 0.1 · (h − h_prev)/dt
```

`a_static` 是静止时的 Z 轴加速度，作为 1g 的重力基准。它在**未解锁时持续跟踪**（用一阶低通平滑）——这一点很重要，如果只在第一次解锁的瞬间采样一次，而那次飞机恰好不水平或正在移动，这个基准就会一直错下去。

> **已知的量纲问题**：上面式子里的加速度项是加速度计的原始 LSB，位置项是 mm/s，两者量纲并不统一，靠 0.9/0.1 的权重凑出可用效果。要进一步提升定高精度，应当把加速度换算成物理单位（LSB × 9.8/16384 m/s²）并与高度统一到同一量纲后再融合，但这样会改变环路增益，需要重新整定高度环参数。

### 5.3 测距野值剔除

激光测距对地面材质敏感，深色或强反光地面会偶发跳变；水平飞行时激光斜射地面，读数也会失真。处理方式是**沿用上一次有效值**：

```c
if(COM_ABS((int16_t)(height - lastHeight)) > 500 ||      /* 单次跳变过大 */
   COM_ABS(joyStick.PIT - 500) > 100 ||                  /* 正在俯仰打杆 */
   COM_ABS(joyStick.ROL - 500) > 100)                    /* 正在横滚打杆 */
{
    return lastHeight;
}
```

### 5.4 定高状态机

| 状态 | 动作 |
| --- | --- |
| 0 | 待机。清空 PID 状态；未解锁时持续跟踪重力基准；满足"已解锁且定高标记置位"则转 1 |
| 1 | 记录进入定高时的油门与高度，转 2 |
| 2 | 每 5 个控制周期算一次串级 PID；油门变化超过 100 或定高标记被清除则退回 0 |

## 6. 电机分配（X 字型机架）

```
       机头
   左上 ◢   ◣ 右上
      ╲     ╱
      ╱     ╲
   左下 ◤   ◥ 右下
```

各轴对电机的贡献：

| 轴 | 增大方向 | 减小方向 |
| --- | --- | --- |
| 横滚 Roll | 左上 + 左下 | 右上 + 右下 |
| 俯仰 Pitch | 左上 + 右上 | 左下 + 右下 |
| 偏航 Yaw | 左上 + 右下 | 左下 + 右上 |

代码实现：

```c
int16_t speed = (int16_t)(joyStick.THR * THROTTLE_GAIN);   /* 0.7 */

motorLeftTop.speed     = speed + roll + pitch + yaw;
motorLeftBottom.speed  = speed + roll - pitch - yaw;
motorRightTop.speed    = speed - roll + pitch - yaw;
motorRightBottom.speed = speed - roll - pitch + yaw;
```

最后是定高输出的**公共叠加**：`zSpeedPID.result` 会加到 4 个电机上，因为它改变的是总升力，不影响姿态。

`Inf_Motor_SetSpeed()` 会把每个电机的值限幅到 0 ~ 1000 再写入定时器比较寄存器，所以即使 PID 输出发散也不会产生非法占空比。

## 7. 调参流程

姿态环按 **内环 → 外环** 的顺序调：

| 步骤 | 目标 | 现象判断 |
| --- | --- | --- |
| 1. 内环 P 极性 | 确定方向 | 错误：加速下跌；正确：缓慢平滑下跌 |
| 2. 内环 P 大小 | 回正平滑 | 太大开始高频抖动，太小回正迟缓 |
| 3. 外环 P 极性 | 确定方向 | 错误：持续旋转；正确：回到初始姿态 |
| 4. 外环 P 大小 | 回正速度 | 允许少量震荡，观察回正快慢 |
| 5. 内环 D | 抑制震荡 | 极性错：震荡加剧；对：震荡减弱 |
| 6. 外环 D | 前一步不足时再用 | — |
| 7. I（可选） | 消除静态误差 | 启用时务必配上积分限幅 |

高度环同理：先调 Z 轴速度内环，再调高度外环。

**所有参数都在 `App/flight/App_Flight.c` 顶部的结构体初始化里**，改完重新编译即可。注意外场调试时先在低空、有保护的情况下验证。
