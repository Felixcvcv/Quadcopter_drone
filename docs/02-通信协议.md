# 通信协议

## 1. 物理层

| 项目 | 配置 | 说明 |
| --- | --- | --- |
| 芯片 | Si24R1（NRF24L01 引脚与寄存器兼容） | 2.4 GHz GFSK |
| 速率 | 2 Mbps | `RF_SETUP = 0x0f` |
| 发射功率 | 7 dBm | 同上 |
| 射频通道 | 111 | 收发双方必须一致（`Inf_Si24R1.h` 的 `CH`） |
| 地址宽度 | 5 字节 | 收发地址相同：`0A 01 07 0E 01` |
| CRC | 16 位使能 | 硬件层 CRC |
| 自动应答 | 通道 0 使能 | `EN_AA = 0x01` |
| 自动重发 | 10 次，间隔 250 µs + 86 µs | `SETUP_RETR = 0x0a` |
| 载荷长度 | 18 字节定长 | `RX_PW_P0` 与发送端一致 |

收发方向：**遥控器只发，飞控板只收**。飞控板上电后配置为接收模式并等待数据；遥控器配置为发送模式，每 6 ms 发一帧。

## 2. 帧格式

一帧固定 18 字节，布局如下（大端，即高字节在前）：

| 偏移 | 长度 | 字段 | 取值范围 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 1 | `FRAME_0` | `0x11` | 帧头 |
| 1 | 1 | `FRAME_1` | `0x22` | 帧头 |
| 2 | 1 | `FRAME_2` | `0x33` | 帧头 |
| 3 | 1 | `len` | 10 | 载荷长度（不含帧头与校验和） |
| 4 ~ 5 | 2 | `THR` | 0 ~ 1000 | 油门 |
| 6 ~ 7 | 2 | `YAW` | 0 ~ 1000 | 偏航 |
| 8 ~ 9 | 2 | `PIT` | 0 ~ 1000 | 俯仰 |
| 10 ~ 11 | 2 | `ROL` | 0 ~ 1000 | 横滚 |
| 12 | 1 | `isPowerDown` | 0 / 1 | 关机命令，单次触发 |
| 13 | 1 | `isFixHeight` | 0 / 1 | 定高切换，单次触发 |
| 14 ~ 17 | 4 | `checksum` | — | 累加校验和 |

### 摇杆行程量的定义

- 遥控器把 ADC 原始值（0 ~ 4095）换算成 **0 ~ 1000** 的行程量
- `500` 是摇杆中位
- 油门以 `0` 为最低位；另外三个通道以 `500` 为中位

飞控板侧对姿态通道的换算是 `(值 - 500) × 0.04`，即满量程 ±500 对应期望姿态角 **±20°**。

### 单次触发字段

`isPowerDown` 与 `isFixHeight` 都是"事件"而不是"状态"，因此约定：

- 发送端：组装完帧后**立即清零**，保证一个事件只发一帧，不会因为持续为 1 而被反复响应
- 接收端：`isPowerDown` 读到 1 就通知电源任务关机；`isFixHeight` 读到 1 就**取反**本地定高状态

## 3. 校验

### 累加校验和

对第 0 ~ 13 字节（帧头 + 长度 + 载荷）做 32 位无符号累加，把结果按大端写入第 14 ~ 17 字节：

```c
static uint32_t App_Communication_Checksum(const uint8_t *buf, uint8_t len)
{
    uint32_t sum = 0;

    for(uint8_t i = 0; i < len; i++)
    {
        sum += buf[i];
    }

    return sum;
}
```

用 32 位累加而不是 8 位，是为了避免求和过程中的溢出歧义。

### 接收端的三级校验

只校验帧头是不够的——受干扰时帧头可能碰巧正确而载荷已经错了。因此接收端按顺序校验：

1. **帧头**：三个字节全对，确认这是自己的遥控器发的
2. **长度**：`RX_BUFF[3] == 10`
3. **校验和**：本地重算的累加和与帧内 4 字节一致

任何一级不过，整帧丢弃并返回失败，调用方按"本周期没收到数据"处理。这样脏数据不会进入控制链路。

## 4. 时序与链路状态

| 项目 | 值 | 来源 |
| --- | --- | --- |
| 发送周期 | 6 ms（约 167 帧/秒） | `COMMUNICATION_EXEC_CYCLE` |
| 失联判定 | 连续 200 次未收到有效帧 ≈ 1.2 s | `LOST_FRAME_LIMIT` |
| 上电初值 | 计数值直接置为上限 | 避免刚上电还没收到数据就显示"已连接" |

一次重发最多 10 次，耗时远小于 6 ms，不会阻塞下一帧。

发送端加超时上限（`TX_POLL_LIMIT`）：射频异常时不会一直轮询状态寄存器死等。这一点很重要，因为发送调用点位于临界区内，死等会连带关中断。

## 5. 解锁状态机

解锁动作在飞控板侧的通讯任务里实现，由油门位置序列驱动，防止误触：

```
                 THR ≥ 960
   THR_FREE ─────────────────▶ THR_MAX
      ▲                          │ 持续 1.2 s
      │ 未坚持满 1.2 s           ▼
      │                     THR_MAX_LEAVE
      │                          │ THR ≤ 20
      │ 中途抬起                 ▼
      └────────────────────  THR_MIN
                                 │ 持续 1.2 s
                                 ▼
                             THR_UNLOCK ── 油门停在最低 60 s ──▶ THR_FREE(自动上锁)
```

- 除 `THR_UNLOCK` 外，其余状态一律返回"未解锁"，并且强制退出定高（未解锁时不允许定高）
- 失联时立即回到 `THR_FREE` 并退出定高
- 解锁后油门需大于 30 电机才会转动（`THROTTLE_MIN`）

## 6. 链路调试

因为链路是单向的，调试时可以用 USB 转 2.4G 模块把遥控器的帧抓下来解析。下面这个脚本按协议解析一串十六进制字节：

```python
def decode(buf: bytes) -> dict:
    assert len(buf) == 18, f"帧长应为 18, 实际 {len(buf)}"
    assert buf[0:3] == b"\x11\x22\x33", "帧头错误"
    assert buf[3] == 10, f"载荷长度错误: {buf[3]}"

    total = sum(buf[0:14]) & 0xFFFFFFFF
    frame = int.from_bytes(buf[14:18], "big")
    assert total == frame, f"校验和错误: 计算 {total:#x} / 帧内 {frame:#x}"

    return {
        "THR": int.from_bytes(buf[4:6], "big"),
        "YAW": int.from_bytes(buf[6:8], "big"),
        "PIT": int.from_bytes(buf[8:10], "big"),
        "ROL": int.from_bytes(buf[10:12], "big"),
        "power_down": buf[12],
        "fix_height": buf[13],
    }


if __name__ == "__main__":
    import sys

    for line in sys.stdin:
        print(decode(bytes.fromhex(line.strip())))
```

## 7. 扩展协议

要新增一个字段，需要同步修改**三处**，顺序如下：

1. `Common/config/Com_Config.h` 里的 `RF_PAYLOAD_LEN`（+1）
2. 遥控器 `App_Communication_SendJoyStickData()`：在载荷区追加字段，`len` 与校验和会自动跟随
3. 飞控板 `App_Communication_ReceiveJoyStickData()`：按同样的偏移解析

`RF_FRAME_LEN` 会自动推导，`Inf_Si24R1.h` 的 `TX_PLOAD_WIDTH`/`RX_PLOAD_WIDTH` 也直接引用它，因此**不需要改动射频驱动的配置**——这是把帧长定义收到一处的好处。改动后务必确认新的总长仍不超过 Si24R1 的 32 字节上限。

## 8. 射频驱动要点

`Inf_Si24R1.c` 把芯片的 ShockBurst 流程封装成几个函数：

| 函数 | 作用 |
| --- | --- |
| `Inf_Si24R1_Check()` | 自检：往地址寄存器写一组数据再读回比对 |
| `Inf_Si24R1_TXMode()` / `RXMode()` | 写入发送/接收模式所需的全部寄存器 |
| `Inf_Si24R1_TxPacket()` | 写 TX FIFO → 拉高 CE → 轮询状态直到 `TX_OK` 或 `MAX_TX` |
| `Inf_Si24R1_RxPacket()` | 读状态寄存器 → 有数据则读 FIFO 并清空 |
| `Inf_Si24R1_FlushTx()` / `FlushRx()` | 清 FIFO（注意这是单字节命令，后面不需要跟数据） |

寄存器映射与位定义完整列在 `Inf_Si24R1.h` 中，便于对照数据手册。
